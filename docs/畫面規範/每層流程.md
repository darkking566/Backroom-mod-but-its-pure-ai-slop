# 每一層的畫面標準流程（SOP，第一版，2026-11-25）

做一層新的樓層，或重做一層的畫面時，照這個順序做。規則（清晰度、顏色、模型、燈）見 [風格規範.md](風格規範.md)。

## 0. 開工前

- `git status` 看有沒有別人改到一半的東西；先抓 GitHub 合併朋友的進度。
- 同一時間只有一邊跑 Gradle（見 `CLAUDE.md`）。`play.bat` 開著遊戲時也不要跑測試。

## 1. 收集參考

- 讀 wiki 原文（Wikidot、中文維基），下載頁面上所有照片，排成一張對照圖。
- 有的話再找影片或其他遊戲的畫面，只用來看氣氛，不拿素材。
- 寫下看得到的特徵：材質、顏色、天花板多高、房間多大、燈的種類和狀態、有多暗、有什麼危險。

## 2. 填規格表

在 `docs/企劃書/5-樓層/<層>/README.md` 加一節「畫面規格」，照下面的表填：

| 項目 | 填什麼 |
|---|---|
| 材質 | 牆、地、天花板、特殊面各用哪個材質（從材質庫挑，沒有的列出來要新做） |
| 顏色 | 從照片取的主色，冷或暖 |
| 尺寸 | 天花板高度、走道寬度、房間大小 |
| 燈 | 燈具種類；亮／壞／閃爍／快壞的比例；光的顏色 |
| 氣氛 | `Look.Mood` 的三個數：多遠開始黑、多遠全黑、衰減 |
| 光影 | 這層開光影要特別注意的（例如水面、玻璃、發光物） |
| 道具 | 要擺的道具：已有的、要新做的（新做的交給 Gemini，附尺寸和三種版本） |
| 掉落 | 照 [`docs/企劃書/3-合成/各層收集.md`](../企劃書/3-合成/各層收集.md) 的格式補這一層 |

## 3. 材質

- 用共用材質工具產生（目前是 `tools/make_level0_realistic.py` 的做法，正在整理成每層填設定就能用的工具包）。
- 每張都要有 `_n`、`_s`；9 種髒舊變體照統一編號。
- 存檔後跑 `py -I tools/resize_realistic.py`，整格的面縮到 128、道具縮到 64。
- 產生後看新舊對照圖，再跟參考照片比。

## 4. 模型與道具

- 先從共用零件挑；這層特有的才新做。
- 新道具開需求給 Gemini：實際尺寸、貼圖 64×64（整格的面 128×128）、完好／損壞／穿模三種版本。

## 5. 光

- 擺燈具，設定各狀態的比例。
- 在 `Look.Mood` 加這層的一行。
- 光的顏色照規範第四節。

## 6. 驗收

- 不開光影：`gradlew runClientGameTest -Plevels=N`
- 開光影：`gradlew runClientGameTest -Plevels=N -Pshaders`（會從 `run/` 拿 Iris、Sodium 和光影包，套用 `docs/畫面規範/光影設定/` 的推薦設定）
- 兩組截圖跟參考照片並排，看：暗的地方夠不夠暗、遠處有沒有沉進黑暗、材質細節看不看得出來、有沒有一格一格的格線感。
- 不對就回到第 3～5 步調整。

## 7. 收尾

- 更新這層的 README、[各層收集](../企劃書/3-合成/各層收集.md)、`CREDITS.md`（新的照片素材）。
- 現況或待辦有變就更新 `tasks/todo.md`；做了什麼留在 git 提交紀錄。
- 只提交自己的改動；推上 GitHub 前先問使用者。
