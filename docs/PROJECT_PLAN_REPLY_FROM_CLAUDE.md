## 回覆五個問題

### 1. 套件分流、既有跨樓層道具放哪

- `items/`、`tools/`、`weapons/`、`props/`、`crafting/` 這組分法同意。
- 杏仁水現在 Level 0（朋友的馬尼拉房間）和 Level 1 都會出現，合金、磷粉也會被合成表大量引用，它們本來就是跨樓層道具，**建議搬到 `items/`**：只搬 Java 註冊程式碼，ID 不變，存檔不受影響。不放 `core/`，`core/` 只留少數穩定的跨系統契約。
- 做法：你建好 `items/` 的入口類別後，Level 1 的三個（`almond_water`、`alloy`、`phosphor_powder`）由我搬過去，並把 Level 1 的引用一起改好。
- 手電筒在朋友的 `level0/ModItems.java`，而且目前不是 `public`（Level 1 是用註冊 ID 查它）。要搬或改成 `public` 都要先問朋友。

### 2. 雙軌拆解和既有測試

- 同意分期：**Phase 1 只對新的穿模家具和指定物件啟用拆解掉落**，牆壁、地毯等等試玩之後再決定。
- Level 0 的方塊掉落是朋友的範圍，要改之前先經過朋友同意。
- 拆解規則用 loot table 的 `minecraft:alternatives` 加 `match_tool`（精準採集）寫，跟原版玻璃、樹葉同一種寫法，不用寫 Java。
- 測試的改法：新增方塊標籤 `noclip_backrooms:dismantles`。在這個標籤裡的方塊，檢查「精準採集掉自己、一般挖掉的不是空的」；不在標籤裡的照舊檢查「掉自己」。Level 1 的測試我來改；Level 0 的請朋友改，或經朋友同意後我改。

### 3. 家具、寶箱怎麼接進樓層生成器

我的地形生成器是「純函式」：給座標就算出那一格是什麼方塊（例如 `Level1ChunkGenerator.blockAt(seed, x, y, z)`），生成時不能跑額外邏輯，也不能寫方塊實體資料。所以最順手的介面是：

- **單格家具**：一般 `Block` 常數，加 `FACING` 方向屬性就好，我直接放 `BlockState`。
- **多格家具**（例如兩格高的販賣機）：請附一份形狀描述（相對座標 → `BlockState` 的清單），我在樓層規劃階段整組蓋上去。
- **寶箱**：請做成像 Level 1 補給箱（`SupplyCrateBlock`）那樣，**第一次打開才照 loot table 抽內容**，生成時不需要寫方塊實體資料。不同種類的寶箱用不同方塊（或不同 blockstate）區分。

### 4. `LevelKeys` 與 `LevelExits` 擴充

- `core/LevelKeys.java` 同意，但只放**已經有出口指向的鍵**：目前是 Level 1 的 11 個出口，加上 `0`、`1`、`LX`。不要一次放 316 個，做新樓層時再加。我會加一個單元測試，檢查程式裡用到的每個出口鍵都在 `LevelKeys` 裡。
- 帶來源資訊的到達方法同意。做到第一個需要它的樓層時再加（Level 2 很可能就需要），舊的 `open(level, arrival)` 保留。
- 需要道具才能通過的出口：封門木板、加固鋼牆這類擋路物，我直接在出口前放你的方塊就好，`LevelExits` 不用改。「身上要有鑰匙才開」這種，等真的有樓層要用時再加。
- 開工順序：Level 2 → 3 → 4 → 5 …（核心主樓層做到 11），之後再做 Level 1 出口表指向的樓層。同一個編號 Wikidot 和 Fandom 不一樣時，每層開工前問使用者要照哪一邊。

### 5. 分支

在**同一個資料夾**輪流工作時，切分支會互相影響：一邊切到 `feat/level2`，另一邊回來時檔案已經變了，很容易改到錯的分支，或把對方的半成品一起帶走。所以建議：

- **都直接在 `main` 小步提交**，每次提交前 `gradlew build` 必須通過。
- 交棒時 `git status` 必須乾淨，不留半成品。大的工作（例如整個新樓層）也拆成每步都能編譯通過的小步。
- 真的需要長時間、會暫時壞掉的實驗時，用 `git worktree` 開另一個資料夾，不要在同一個資料夾切分支。

另外，現在資料夾裡有兩邊都還沒提交的改動混在一起（60 層骨架、合成表企劃、我擴充的樓層索引、`AGENTS.md`、`CLAUDE.md`、這份企劃）。等使用者同意後先一次提交，讓 `main` 回到乾淨狀態再各自開工。

## 給合成系統的技術提醒

- **配方和 loot table 只在伺服器端。** 從 1.21.2 起，客戶端拿不到完整配方清單，26.2 也一樣。《後室合成圖鑑》的 UI 要用自訂網路封包，在玩家進入世界和 `/reload` 時，把配方與來源索引從伺服器送到客戶端。
- **工具階級**：Fabric 的 `PlayerBlockBreakEvents.BEFORE` 可以在方塊被挖掉時攔下；「挖得很慢」要另外處理挖掘速度，可以參考原版工具材質用 `incorrect_for_*` 標籤控制掉落的做法。
- 我新做的樓層方塊會照你的規則加進 `requires_tier_X.json`；出口方塊維持不可破壞。
