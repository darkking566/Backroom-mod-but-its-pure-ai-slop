## 專案總覽（原企劃書第 1 節，照現況改）

- **100% 原創的獨立模組**：不拿現成的大型玩法模組拼裝。這樣探索有新鮮感、數值完全自己掌控，之後擴充到 300 層以上和新裝備也好維護。
- **遊戲方向**（2026-11-25 起）：**恐怖、逃離後室**。玩家很脆弱，怪物很難打；回到地面後要在期限內回去交配額。見 [遊戲玩法](1-gameplay/README.md)。
- **借鑑的遊戲**：

| 遊戲 | 借什麼 |
| --- | --- |
| 《狐霖的後室 RPG》 | 層數算法（Level 編號和「第幾層」分開）、安頓據點、探索撤離 |
| 後室 Wikidot／Fandom／中文維基 | 每一層的長相、實體、出口；悲屍化 |
| 《致命公司》 | M.E.G. 配額與期限、強制再部署 |
| 《深海迷航》 | 帶著倒數逃出來，解藥原料在深處 |
| 《非生物因素》 | 辦公雜物拼裝求生裝備、分階密碼門駭客器、工具分級拆解家具 |
| 《異星工廠》 | 標準化中間零件、三色電路、研究瓶、插件晶片 |
| 《星露谷物語》 | 星級品質、加工致富、收集包、盲盒 |
| 《Minecraft》 | 主世界、超大型蜘蛛網合成台、原版物資融入配方、原版地獄與終界的後室化 |

- **用到的函式庫**：
  - **JEI**：查配方【已做】。
  - **GeckoLib**：原企劃書想用來做動畫。實際上怪物、人物、機器人用自己寫的盒子骨架（`BoxRig`，讀 Blender 匯出的規格檔），武器動畫自己寫，沒有用 GeckoLib。
  - **Curios**：原企劃書想用來做飾品欄。還沒用，流派徽章要做時再評估。
- **光影**：搭配 Iris＋Complementary Unbound 的推薦設定（見 [`docs/look/`](../look/README.md)）。

## 工程規範（原企劃書第 7 節＋協作交接書）

1. **資料驅動，不硬寫**：
   - 配方全部是 JSON（工作站配方在 `data/noclip_backrooms/backrooms_recipes/station_recipes.json`，原版工作台在 `data/noclip_backrooms/recipe/`），調數值、改材料、刪配方只改 JSON；
   - 方塊的掉落用 loot table；
   - 武器、道具、家具盡量用共用的父類別：理智扣除與不足鎖定、扣血武器、槍械掛敏捷、可拆解家具。
2. **物品標籤**：配方盡量引用統一標籤（例如 `#noclip_backrooms:electronics`、`scrap_metal`、`office_junk`），之後加新材料能直接接進舊配方。
3. **ID 永不改名**：方塊、物品、音效、維度的 ID 一旦用了就不改，避免舊存檔壞掉；名稱和說明可以改。
4. **地形生成是純函式**：每一層的生成器是「給座標就算出這一格是什麼方塊」，生成時不能跑額外邏輯、也不能寫方塊實體資料。所以：
   - 單格家具：一般方塊，加 `facing` 方向屬性；
   - 多格家具：附一份形狀描述（相對座標 → 方塊狀態）；
   - 寶箱：第一次打開才照 loot table 抽內容。
5. **出口**：任何樓層的出口都呼叫 `LevelExits.use(player, "目的層")`。目的層還沒做好時自動顯示「尚未開放」；做好後呼叫 `LevelExits.open(...)`，所有指向它的出口就一起接通。要道具才能過的出口，先在出口前放擋路的方塊（封門木板、加固鋼牆）。
6. **配方與 loot table 只在伺服器端**：客戶端拿不到完整配方清單，遊戲內圖鑑要用自訂封包把資料送給客戶端。
7. **玩家資料**：等級、能力值、理智、帳戶、層數等都用 Fabric 的附加資料存在玩家身上，同步給本人（隊友看不到你的理智）。
8. **貼圖與效能**：整格的面 128×128、道具 64×64，附 labPBR 法線與高光貼圖；細節見 [`docs/look/STYLE_GUIDE.md`](../look/STYLE_GUIDE.md)。
9. **300+ 樓層不能開 300 個維度**：風格相近的樓層合在少數維度裡，用超大座標分區或生態域切換；30～50 個核心樓層精細做，其餘用資料驅動的樓層引擎批量擴充。見 [樓層](5-levels/README.md)。

## 分工與協作

| 誰 | 負責 |
| --- | --- |
| 朋友（GitHub 上推 `origin/main` 的那位） | Level 0 |
| Claude | Level 1 和之後的樓層、跨樓層出口（`core/LevelExits`）、怪物 AI 與各層生怪、玩法系統（層數、死亡與撤離、週期與配額、經驗）、測試 |
| Gemini（Antigravity） | 合成系統、物品、工具、武器、家具、寶箱、怪物模型與動畫、悲屍化排斥與藥 |

- **大家都在同一個資料夾 `Desktop\Backroom` 的 `main` 輪流工作**。同一時間只有一邊改檔案或跑 Gradle；交棒時 `git status` 要乾淨，不留半成品。規則全文見根目錄的 `AGENTS.md`。
- **小步提交**：每次提交前 `gradlew build` 要通過；大的工作拆成每步都能編譯的小步。需要長時間、會暫時壞掉的實驗，用 `git worktree` 另開資料夾，不在同一個資料夾切分支。
- **共用的檔案**按區塊追加，不重排對方的條目：
  - `BackroomsMod.java`、`BackroomsClient.java`
  - 語言檔、`sounds.json`、挖掘標籤
  - `CLAUDE.md`
- 推上 GitHub 前先把朋友的進度抓下來合併；推送要使用者同意。
- 程式和資源照樓層分資料夾（`level0/`、`level1/`……），跨樓層共用的放 `core/`，怪物放 `monsters/`；什麼放哪見根目錄的 `README.md`。
